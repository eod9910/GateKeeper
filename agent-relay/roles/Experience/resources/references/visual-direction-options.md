# Visual Direction Options

Use these as starting points when Experience generates two or three concept
options. Adapt them to the domain and avoid treating them as fixed themes.

## Quiet Control Room

- Feeling: calm, competent, operational.
- Fit: RAG consoles, observability, admin tools, review queues, dashboards.
- Layout: compact navigation, strong alignment, restrained density, persistent
  status.
- Color: neutral base with two functional accents, not a single-hue wash.
- Typography: small-to-medium, readable, tabular where data matters.

## Friendly Workshop

- Feeling: approachable, clear, capable.
- Fit: tools for non-experts, onboarding-heavy products, internal utilities.
- Layout: grouped tasks, helpful empty states, direct labels, forgiving spacing.
- Color: warm-neutral or balanced light palette with practical accents.
- Typography: plain and readable, with enough size for guidance text.

## Technical Notebook

- Feeling: precise, research-oriented, inspectable.
- Fit: analysis tools, developer apps, knowledge work, document/RAG workflows.
- Layout: split panes, source/detail views, annotations, provenance or logs.
- Color: neutral surfaces with semantic states for confidence and risk.
- Typography: strong monospace support only where code, ids, or logs appear.

## Visual Studio Surface

- Feeling: creative, spatial, exploratory.
- Fit: builders, canvases, graph tools, image/media tools, visual workflows.
- Layout: full-bleed work area, tool rail, inspector, direct manipulation.
- Color: balanced contrast that keeps the canvas primary.
- Typography: compact labels, clear tooltips, low-friction controls.

## Public Product Signal

- Feeling: memorable, confident, immediately understandable.
- Fit: landing pages, branded products, venues, portfolios, public launches.
- Layout: first viewport shows the product/place/person/object, not only copy.
- Color: brand-led but controlled; avoid generic gradients as the main idea.
- Typography: hero scale only for true hero content, not routine panels.

## Option Rules

- Generate options that differ in structure, workflow, and mood, not just color.
- Name what each option is good for and what it sacrifices.
- Keep examples concrete enough that Builder can implement them later.
- For user-facing apps, prefer app surfaces over marketing pages unless the
  product is actually a landing or brand surface.
